# CEO Plan: CaseHelper — Social Worker Toolbelt

Generated by /plan-ceo-review on 2026-04-28
Branch: unknown | Mode: SELECTIVE EXPANSION
Repo: casehelper

## Vision

A cross-platform toolbelt for Salvation Army Australia social workers, starting with LLM-assisted case notes. The case plan is the hub — scheduling assistant helps workers decide what to do and when, Todoist reflects the schedule, and completion updates the case plan. Archive search makes old cases findable. Data is local-first (SQLite on disk). LLM calls require connectivity; when offline, manual text entry is used. Browser automation requires the legacy web app to be accessible.

### 12-Month Ideal
Complete social worker toolbelt: case notes, case plans with smart scheduling, Todoist sync, archive with full-text search. All LLM-assisted. Cross-platform. Team-deployable.

## Architecture Decisions

- **Tauri shell + modular Rust crates** — Approach B from design doc. Each module (LLM, browser, Todoist) is independently testable.
- **CaseHelper as source of truth** — CaseHelper is the planner/scheduler. Todoist is the display. Completion status from Todoist is one input among several, not the primary feedback.
- **Case plan as the scheduling hub** — Scheduling assistant operates on case plan items, not raw Todoist tasks. Flow: case note → case plan items → scheduling assistant → Todoist → completion feeds back to case plan.
- **Local-first data persistence** — SQLite on disk for all data. Auto-save every 30 seconds. Crash recovery on relaunch. Network failures queue locally and retry with exponential backoff (max 3 retries, then surface error to worker).
- **Offline mode (partial)** — LLM drafting falls back to manual text entry when offline. Browser automation requires the legacy web app to be accessible. Full offline-first with sync is deferred to TODOS.md.
- **LLM redaction filter** — Preprocessing step before LLM inference. Configurable term list matched via regex. Replaces matched terms with [REDACTED] tokens. Does not affect locally stored notes.
- **Scheduling LLM context strategy** — Retrieval: most recent 10 case notes + all active case plan items + case metadata (client name, case stage, priority). If context exceeds model token limit, oldest notes are dropped first. Context is constructed per-scheduling run, not cached long-term.
- **Feedback loop** — Case plan completion is updated via: (a) Todoist task completion → CaseHelper polling detects → case plan item marked complete, OR (b) worker manually marks complete in CaseHelper. Todoist completion is the fastest path but not the only one — worker can always update directly in CaseHelper.
- **LLM provider configuration** — Default: Ollama (local, OpenAI-compatible API). Settings page allows switching to OpenAI, Anthropic, or custom endpoint. API key stored in system keychain via Tauri. No data leaves the machine when using Ollama.
- **Settings page** — Worker configures: LLM provider, endpoint URL, API key, model name, redaction list. Future: Todoist OAuth, preferences.

## Accepted Scope (added to this plan)

1. **Case notes (v1 — no browser automation)** — LLM-assisted drafting from raw worker input. Worker records observations, LLM drafts structured case notes, worker reviews/edits in preview pane. Worker manually copies the approved draft into the legacy web app. This version ships first and delivers immediate value without requiring browser automation to be resolved. v1.1 adds browser automation once Q1-Q4 are resolved.
2. **Settings page** — LLM provider configuration: dropdown (Ollama, OpenAI, Anthropic, custom), endpoint URL, API key (masked), model name. Redaction list editor. Todoist settings (when added). Accessible from the case dashboard.
3. **Smart scheduling assistant** — Triggered from the case plan section when items need scheduling. Considers deadlines, case priority, workload across all open cases. Presents suggestions: "do today / this week / this month." Worker approves or adjusts before items push to Todoist. LLM-powered reasoning across full case context (case history, past notes, plan items). Not a push notification system — worker opens it when planning their week.
4. **Archive search** — SQLite FTS5 on case notes and plan items. Search by client name, keyword, date range, case status. Accessible from the case dashboard. Closed cases remain findable. Search results link directly to the archived case.
5. **Configurable redaction list** — Stored in CaseHelper settings (SQLite). Applied at LLM inference time: text passes through redaction filter before being sent to the LLM endpoint. Default presets: personal names, organization names, locations. Worker can add custom terms. Per-draft toggle (anonymization on/off for each draft).

### Unsaved Changes on Case Switch
When a worker switches cases while raw notes have unsaved changes (local state differs from last SQLite save), CaseHelper prompts: "You have unsaved changes in Case A. Save before switching or discard?" Save triggers the debounced save immediately. Discard abandons changes. This prevents silent work loss.

### Draft Editing
The LLM draft in the preview pane is editable. After LLM returns the draft, the worker can make small edits directly in the draft textarea before copying to the legacy app. This supports the "worker refines the draft" workflow without requiring a re-draft call.

### Archive Search Behavior
Archive search triggers on Enter key press only. Worker types query, presses Enter, FTS5 query fires. No debounce — avoids firing queries on every keystroke.

### Draft Validation
Before calling the LLM, validate that raw notes are non-empty (not whitespace-only). If empty, show inline error "Please enter your observations before drafting." No LLM call is made. Prevents wasted API calls on empty input.

## Design Decisions

Added by /plan-design-review on 2026-04-29

### UI Type
**APP UI** — workspace-driven, task-focused, data-dense. Not a marketing/landing page. Calibrate all design decisions against App UI rules.

### Navigation Structure
**Sidebar + top bar.** Left sidebar: case list (always visible). Click case → main workspace shows that case. Right edge: Todoist summary panel (collapsible). Top bar: archive search + settings gear icon. Instant case switching, no page reloads.

### Case Note Screen Layout
**Draft primary, raw input secondary.** LLM draft occupies the primary visual space. Raw notes input appears above/beside as a smaller textarea. Worker refines the draft, not writes from scratch. Draft is the primary artifact.

### LLM Drafting State
While LLM is drafting: draft pane shows placeholder text "Drafting..." with subtle pulse animation. Raw notes input area is visually dimmed (reduced opacity). Signals that input was received and work is in progress.

### Auto-Save Indicator
**Transient "Saved" text.** Appears bottom-right of the note area when auto-save fires. Fades in briefly (~1.5s), then fades out. Unobtrusive but findable when worker looks for it.

### First Launch Empty State
Case list shows: "Welcome to CaseHelper" heading + "Add your first case" button. Warm, single CTA, no clutter. No illustration — text + button is sufficient for a professional tool.

### Responsive Behavior
**Full sidebar on desktop (1024px+).** Sidebar collapses to hamburger menu on mobile (<1024px). Todoist panel accessible from hamburger menu on mobile. Desktop keeps full layout.

### Typography
**Geist** (Google Fonts, or similar professional sans-serif). Not SF Pro (too Mac-specific), not Inter (AI slop default), not system-ui. Geist is free, professional, has character, and loads once and caches.

### Color System
- Background: warm neutral (#f8f8f6 or similar off-white)
- Surface: white (#ffffff)
- Text primary: near-black (#1a1a1a)
- Text secondary: medium gray (#6b7280)
- Accent: slate blue (#4a5568) — used for active states, CTAs, highlights. NOT purple, NOT bright blue.
- Border: subtle (#e5e5e5)
- Error: desaturated red (#dc2626)
- Success: desaturated green (#16a34a)
- All colors as CSS custom properties

### Redaction Toggle Location
**In the tab's top bar** — next to the "Draft" button. Always visible on the Notes tab, doesn't take space in the editing area. Worker sees it before triggering a draft.

### Todoist Summary Panel
**Right edge, always accessible, collapsible.** Shows tasks tagged to the selected case. Toggle button to collapse/expand. Stays visible while worker is on Notes or Plan tabs.
